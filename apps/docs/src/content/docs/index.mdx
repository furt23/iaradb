## How it works

Queries are built as lazy plans and run only when they are collected or written. At run time the engine optimizes the plan, splits it into pipelines, and runs each pipeline in parallel on a thread pool. The input is divided into morsels, such as the row groups of a Parquet file or the byte ranges of a CSV file, and each morsel is processed by one worker. Results are Arrow record batches: a `DataFrame` holds them in memory, and a sink such as `sink_parquet` writes them out as they are produced. Aggregations, joins and sorts reserve their memory from a process-wide pool and spill to disk when it is full.

## Interactive Example

```python
import iara
from iara import functions as F

# 1. Lazily scan Parquet data
plan = (
    iara.scan_parquet("data/sales/*.parquet")
    .filter(F.col("amount") > 100.0)
    .group_by("region")
    .agg(
        total_revenue=F.col("amount").sum(),
        avg_order=F.col("amount").mean(),
        order_count=F.len(),
    )
    .sort("total_revenue", descending=True)
)

# 2. Inspect the optimized query plan
print(plan.explain())

# 3. Collect the result in parallel
df = plan.collect()
df.show()
```
